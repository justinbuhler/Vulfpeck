# 0017. Loop, scope and budget limits are hooks, not prose

Status: proposed
Date: 2026-10-23
Components: .claude/hooks/loop_guard.py, .claude/hooks/scope_guard.py, .claude/hooks/budget_guard.py, .claude/hooks/turn_guard.py, scripts/loop_reset.py, scripts/scope.py, scripts/guard_lib.py

## Context

`AGENTS.md` carried "Stop and reassess", "Scope" and "Turn completion" as prose marked "enforcement planned". An agent that repeats a failing command, drifts outside its task, runs without limit or ends a turn announcing work is stopped only if it reads and obeys the prose. Claude Code, Codex and Gemini all run the guards in `.claude/hooks/` through one `harness.toml` table (ADR 0015), so a rule enforced there is enforced under all three. Probed on Claude Code 2.1.309: a Bash command that exits non-zero fires `PostToolUseFailure` with `error` "Exit code N\n...", not `PostToolUse`, and a user-level hook may rewrite the command (`rtk ...`) after PreToolUse; Codex and Gemini send PostToolUse for success and failure (Gemini's `llmContent` carries an `Exit Code: N` line when non-zero). Gemini's AfterAgent payload carries `prompt_response` and `stop_hook_active`.

## Decision

Four gates, each registered once in `harness.toml`, with the shared helpers in `scripts/guard_lib.py` (state, payload reading, the one list of test commands, rule quotes). State is local, never tracked, under `<git common dir>/harness/`: `loop/<session_id>.json` (loop and turn counters), `loop/<session_id>.budget.json`, and `scope/<branch>.json`. A missing or corrupt state file is reset with a one-line notice. Each block, deny and reset appends one line through `scripts/harness_events.py`.

- `loop_guard.py` (PreToolUse Bash and Edit|Write, PostToolUse Bash and Edit|Write, PostToolUseFailure Bash). A failure fingerprint is the sha1 of the normalised command (rtk prefix, leading env assignments and `cd <dir> &&`, redirections and trailing pipes to cat, tail, head, grep and tee dropped, whitespace collapsed) plus the first error line with timestamps, hex ids and durations replaced, counted only when the command exited non-zero. The 3rd sighting in a session trips the guard with the AGENTS.md rule, the three attempts and `jev.reassess()`'s advice when Jev answers (advice only; Jev cannot unblock); a successful run of a command clears that command's fingerprints. A command byte-identical to the last failed one is denied until an edit or any other Bash command has run. No-progress counts failing tests: a test or lint run (harness.toml commands, `scripts/run.sh`, `gate.sh`, pytest, `tests/` scripts, `plan_tests.py --run`) is a stalled cycle when it fails after edits with no fewer failing items than the previous failing run of the same command (items are `FAIL <name>` and `FAILED <id>` lines and `N failed`; with none, a different error counts as progress); a run after a pass starts a new count. Two stalled cycles block once with the reassess message and reset the count; a second such block in the session denies every test and lint command. A tripped guard denies the failing command (fingerprint trip). An exit status that stays unknown (Codex rollout not yet written after about 2 s) changes no counter. The agent cannot reset: PreToolUse denies Bash that runs `scripts/loop_reset.py` or mutates `harness/loop`, and an Edit or Write into it; a corrupt state file that held a trip stays tripped. The owner or the task runner calls `scripts/loop_reset.py --session <id> --reason "..."`, which records an event; the guard never resets itself. State is keyed by session id plus agent id, so subagents keep their own counters.
- `scope_guard.py` (PreToolUse Edit|Write; Codex apply_patch arrives as Edit or Write). Opt-in through a lease from `scripts/scope.py set --glob ... --max-files N --max-lines N --task "..."`; with no lease it allows silently. A path outside the globs is denied ("out of scope"). An edit that would take the branch's diff against its merge base past max_files or max_lines (untracked files included) is denied; `scope.py check` asks `jev.intent_alignment()` whether the diff still serves the task, and only a wider `scope.py set` unblocks.
- `budget_guard.py` (PreToolUse, every tool). `harness.toml [budget]` sets `max_tool_calls` (400) and `max_minutes` (180) per session, 0 meaning off. One warning at 80%, a deny at 100% telling the agent to write status and stop; a Write or Edit of a file matching `status_glob` (default `**/STATUS.md`, `**/status.md`, `tmp/**/status*.md`) still passes. The clock counts active time only: a gap over 30 minutes between calls is not counted. State is keyed like the loop state. `loop_reset.py --budget` starts a fresh budget.
- `turn_guard.py` (Stop; Gemini AfterAgent). A final message whose last paragraph announces unstarted work (the `ANNOUNCE` regex list in one place) is blocked once with "do it or name the blocker"; `stop_hook_active`, a repeat of the same message, a negation, a question, quoted or code text, a conditional or waiting phrasing ("after you approve", "once you confirm", "wait for your"), a numbered plan, or a paragraph that names a blocker passes.

All four are gates: a crash blocks. `harness.toml` adds `PostToolUseFailure` as a hook event, which only Claude Code has; `render_hooks.py` leaves it out of the Codex and Gemini files and `gaps()` lists it.

## Consequences

The rules marked enforced in `AGENTS.md` hold under all three runtimes, and each guard has a deny and an allow canary per runtime in `tests/test_harness_controls.py`. Limits: an unchanged re-run is allowed after an edit or any other Bash command, so a cat-and-retry loop is held only by the 3-sighting rule; the fingerprint's error line is the first line that reads as an error, so output that varies per run defeats it; Codex's PostToolUse response shape was read from a live probe only for the fields recorded in the proof, and Gemini's rests on the bundled source and tests; a Gemini block on a PostToolUse replaces the tool output with the message; the Claude scope lease binds only Edit and Write, so a Bash `rm`, `mv`, `sed -i` or `cat >` bypasses it; parallel tool calls run their hooks concurrently and can lose a counter update (state is written atomically but read-modify-write is not locked); deleting the loop state with `find -delete` or `python -c` is not caught; a numbered last line in a final message disables `turn_guard`. A passing test or lint run resets the no-progress strikes. Hook and script code must parse on Python 3.11 (`tests/test_py311_syntax.py`; ruff targets py311). "One corrective round per phase", the missing-worktree rule and the dispatch rules stay prose. Jev's advice is text only. This does not change `hook_adapter.py` or the event log format.
